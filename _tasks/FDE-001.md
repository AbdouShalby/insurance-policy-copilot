# FDE-001: Insurance Policy Copilot, phase 1 (ingest service, retrieval API, CRM webhook, eval)

Lead: Claude. Implementer: Codex. Date: 2026-11-16.

## Objective
Build a runnable, tested portfolio project that shows forward-deployed-engineering work: a Python ingest service turns insurance policy documents into cited chunks, a TypeScript API answers questions with citations, and a signed, idempotent CRM webhook lets a client system ask questions automatically. Everything runs locally with no paid API and no real client data.

1. **Ingest service (Python, FastAPI)**
   - `POST /ingest` accepts a document (multipart file: `.pdf`, `.md`, `.txt`) plus `doc_id` and `title`. PDF text via `pypdf`.
   - Splits into chunks (about 500-900 characters, sentence-aware, small overlap), each with `doc_id`, `title`, `chunk_id`, `page` (PDF page or 1 for text), `text`, `lang` (`ar` or `en`, simple heuristic).
   - Returns the chunks as JSON. Stateless: it does not store anything.
   - `GET /health`.
   - Rejects empty or unsupported files with 400 and a clear message; max upload 10 MB (413).
   - Tests with `pytest` (chunking boundaries, Arabic detection, PDF path using a tiny PDF generated in the test, error cases).
2. **API (TypeScript, NestJS)**
   - `POST /documents`: forwards an uploaded file to the ingest service (`INGEST_URL`, default `http://localhost:8001`), indexes the returned chunks.
   - Index: `minisearch` (BM25-style), persisted to `data/index/index.json` so it survives restarts. Re-ingesting the same `doc_id` replaces its chunks.
   - `POST /ask` with `{ "question": string, "top_k"?: number }` returns `{ answer, citations: [{doc_id, title, page, chunk_id, snippet}], mode: "extractive" | "llm" }`. If nothing scores above a threshold, return a clear "not found in the policy documents" answer with empty citations (no guessing).
   - `POST /webhooks/crm`: simulates a client CRM. Body `{ event_id, case_id, customer_question }`. Header `X-Signature: sha256=<hex>` = HMAC-SHA256 of the raw body with `CRM_WEBHOOK_SECRET`. Behaviour:
     - invalid or missing signature → 401, nothing processed;
     - first time an `event_id` is seen → answer the question, store the result keyed by `event_id`, return 200 with the result;
     - same `event_id` again → return the stored result (200) without recomputing (idempotent, safe for CRM retries);
     - concurrent duplicates must not double-process (use an in-process lock or atomic set; document the multi-instance approach, e.g. Redis `SET NX`, in the README).
   - `GET /health`.
   - Validation with `class-validator` (or `zod`), consistent JSON errors.
   - Tests with Jest + supertest: ask with citations, not-found case, re-ingest replace, webhook 401 / 200 / duplicate replay / concurrent duplicate. Mock the ingest HTTP call and the LLM adapter.
3. **Eval**
   - `eval/questions.json`: 15-25 questions over the sample docs, each with the expected `doc_id` (and page when relevant), including 2-3 Arabic questions and 2 questions whose answer is not in any doc.
   - `eval/run-eval` (a TS or Python script) runs the questions against the API (or the retrieval module directly) and prints: retrieval hit rate at k=3, not-found accuracy, average latency. Write the result to `eval/results.md`.
4. **Deployment playbook** (`docs/deployment-playbook.md`): how a forward-deployed engineer would install this at a new insurance client in one day: prerequisites, config/env vars, loading the client's documents, connecting their CRM webhook (secret exchange, retries, idempotency), smoke tests, what to monitor, rollback. Practical and concise.
5. **Config**: `.env.example` files (no real secrets). Ports: ingest 8001, api 3000.
6. Dependencies allowed: Python `fastapi`, `uvicorn`, `pypdf`, `python-multipart`, `pytest`, `httpx`; Node `@nestjs/*`, `minisearch`, `class-validator`, `class-transformer` (or `zod`), `jest`, `ts-jest`, `supertest`, `@types/*`, `typescript`. Anything else: list it under deviations with the reason.
7. Code quality: small modules, typed, no dead code, comments only where the why is not obvious. English everywhere.
