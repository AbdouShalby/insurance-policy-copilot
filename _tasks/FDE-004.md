# FDE-004: Public read-only demo on Vercel (serverless)

Lead: Claude. Implementer: Codex. Date: 2026-11-17.

## Objective
Make the existing NestJS API and demo page deployable as a free Vercel Hobby project, read-only and extractive, so a visitor can open one public URL and ask questions against the five synthetic sample policies. No Python service, Redis or LLM at runtime.

## Context
- Read first: `README.md`, `_tasks/FDE-003.md` (demo mode you built last time), `apps/api/src/app.ts` (`createApp`, `DemoGuard`, `seedSamples`, home page rendering), `apps/api/src/main.ts`, `apps/api/src/index-store.ts`, `apps/api/src/policy.service.ts`, `services/ingest/` (chunker), `samples/policies/`.
- Demo mode (`DEMO_MODE=true`) already blocks uploads, samples, webhooks, and rate-limits `/ask`. Reuse it unchanged.
- At runtime on Vercel there is no Python, no writable disk (except /tmp), no Redis. Requests may hit a cold function instance.
- Decision: the index is built ahead of time from the samples using the real ingest chunker, committed as a static JSON file (synthetic data only, small), and loaded read-only by the function.

## Requirements
1. A Vercel serverless entry that bootstraps the Nest app once per instance (cached promise), with `DEMO_MODE=true` forced and the index loaded from the committed demo index file (read-only; never written). All routes (`GET /`, `GET /health`, `POST /ask`, and the blocked routes returning 403) are served through this one function, using rewrites.
2. Startup must not need the ingest service. If the index file is missing or corrupt, the function returns a clear 503 JSON error, not a crash loop.
3. Cold start target: first `/ask` answered within about 3 seconds locally.
4. `X-Forwarded-For` handling: Vercel sets it; keep the existing one-hop trust in demo mode and state whether that is correct on Vercel (cite the Vercel doc you relied on, or say unverified).
5. The page and the API behave identically to the FDE-003 container demo (read-only note, hidden setup controls).
6. Generated index content equals what the API would build by ingesting the five samples (same chunk ids, pages, text). Add a test that loads the committed index and answers the windscreen question with `motor:p1:c1` and the Arabic medical question with a `medical-ar` citation, and a not-found question with no citations.
